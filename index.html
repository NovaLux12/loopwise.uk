Repository 01 · MIT · Community fork

carelink-bridge

github.com/NovaLux12/carelink-bridgefetch · normalise · upload · v0.2.0

Signs into CareLink the way the official app does, piping Medtronic pump and CGM data into Nightscout automatically. A community fork kept alive while upstream is quiet — carrying the BLE detection fix from upstream PR #2 by @terminalcommand, with the wire-vocabulary correction now in flight.

Safety

mmol/L converted at the source

mg/dL values converted at the SGV site — without it, looping clients would over-deliver insulin.

Safety

Atomic, locked-down credentials

Tokens written atomically with 0600 permissions — wiped only on permanent auth failure, never a blip.

BLE detection, carried upstream

Upstream PR #2 by @terminalcommand, cherry-picked with a regression test. Issues #81 and #73 are open on the wire vocabulary — no 780G data has flowed through it yet.

npm run doctor

One command checks env, CareLink and Nightscout reachability, and token validity. It exits non-zero on failure; nothing calls it automatically yet.

Stale-data watchdog

Warns after 15 quiet minutes without a fetch; optionally POSTs a webhook.

Status-aware retries

Capped backoff with jitter that honours Retry-After; rationale published in eight ADRs.

15-minute deploy

Hardened systemd unit, idempotent installer, compose stack — the user guide budgets about 15 minutes for first-time setup.

Three login strategies

An automated Auth0 POST with PKCE, a visible browser window when CAPTCHA or MFA gets in the way, and a terminal paste as the last resort — nights do not wait.

Alarms surfaced, not sent

CareLink alarms surface as Nightscout devicestatus, priority-1 always logged — never relayed as treatments.

Full docs suite, not a README-and-hope: USER-GUIDE.md ARCHITECTURE.md SECURITY.md CONTRIBUTING.md ROADMAP.md CHANGELOG.md docs/adr/
What you get

Three things, every week.

No dashboard to learn. No SaaS login. You get a brief, a PDF, and a paper trail — and you stay in charge of every decision.

01 01 · Each morning

A live trace read

A one-paragraph morning brief in plain English, pointing at the parts of the overnight trace that warrant a second look. No decisions made for you — flags only.

02 02 · Each week

A weekly PDF

One page you can email to your diabetes team: averages, variability, time in range, lows, highs, basal/bolus split, per-day breakdowns. Every number traceable to its source data.

03 03 · Always

An audit trail

Every confirmed write lands in a 0600 JSONL log on disk. Read it, grep it, hand it to a clinician. Nothing happens without a record.

Repository 02 · MIT · Single-operator fork · Private preview

nightscout-mcp

Model Context Protocol server for Nightscout60 read · 6 gated writes

Claude queries Nightscout data — CGM history, treatments, ISF/CR, AGP/GRI, loop status — and, only with explicit opt-in, logs treatments back. Every write gated and audited.

Safety

Confirm-gated writes

6 write tools dry-run by default; only a literal confirm flag on the same call posts — every write lands in a 0600 JSONL audit log.

Safety

Two-token access control

Read token unlocks the 60 read tools; a separate write token plus master switch unlock the 6 writes. Full-admin refused.

60 read tools

v1, v2 and modern v3 search/history APIs — plus analytics, pattern detection, AGP/GRI and AAPS/loop status.

Token-leak-proof logging

Error paths log exception types, never messages — validators embed rejected input. A canary test enforces it.

Speaks HTTP too

Stdio for Claude Desktop, streamable HTTP for agent clients — non-loopback binds refused unless opted in.

Warns before you do

Startup banner surfaces the two reasons writes would fail: careportal disabled, runtime still loading.

Frequently asked

If yours isn't here, mail the maintainer — the inbox is read by a person.

What exactly is Loopwise Health?

A small, maintainer-run project that keeps the open diabetes plumbing alive — a CareLink-to-Nightscout bridge, a Nightscout MCP server, and a zero-dependency reporting toolkit — with a Claude-powered brief, report and triage workflow on top. See the pipeline for the full picture and built in the open for what's verifiable.

Is it safe? Does it dose insulin for me?

No — nothing here doses insulin or replaces official CareLink safety notifications. It is research and educational tooling only (not a medical device, not FDA approved), and every treatment decision stays with you and your diabetes team; see the roadmap scope note.

Which pumps and CGMs does the bridge support?

Medtronic 780G pumps with Guardian 4 or Simplera sensors, fetched via CareLink the way the official app does — that trio is the active testing surface. Other CareLink-compatible models should work but aren't in the regression suite, and closed-loop control of any kind is out of scope.

How much does it cost?

Free: all four repos are MIT-licensed, with no paid tier, no subscription, and no telemetry. You only pay for the hardware you already own and the small VPS you choose to host the bridge on.

How do I get started?

Read the bridge docs — the USER-GUIDE walks you from a fresh VPS to a working Nightscout + bridge + Cloudflare tunnel stack, budgeting about 15 minutes for the setup itself. Run npm run doctor any time to check the pipe, or mail the maintainer if the docs don't cover it.

Can my clinic use the reports?

That is the whole point of the clinic-reports bet on the roadmap's "next" phase. The toolkit already emits machine-readable JSON plus per-day breakdowns, so a clinic can audit every number — the polished shareable PDF is what's being built next.

Where does my data live?

On your Nightscout instance, which you host — the bridge posts there and nowhere else, the MCP server reads your instance on your machine, and there is no telemetry back to us. Confirmed writes are logged to a 0600 JSONL file on your own disk.

Are you affiliated with Medtronic?

No — an MIT-licensed community fork, kept alive while upstream is quiet, and not affiliated with, endorsed by, or sponsored by Medtronic. If upstream wakes up, we fold our fixes back.
